# 4D Flow MRI 整体流程命令行入口

## 用途与边界

`flow4d.overall_flow` 是现有 Python 模块的串联入口。它不修改 MATLAB，也不把目前未经真实病例验证的结果称为与 MATLAB 等价。为修复实测故障，节点采样和四维解混叠的 Python 模块已有针对性修改。选择输入、速度来源和速度方向由用户决定；程序逐步给出状态、耗时、数组尺寸及输出路径。

## 输入目录与命名

输入选择外层 `DICOM_4D_Qflow`，其中应有 `4D_Qflow_M`、`4D_Qflow_AP`、`4D_Qflow_FH`、`4D_Qflow_RL`。完整运行还需 `mask`、`root` 两个逐层 DICOM 目录。已核对示例目录为 `D:\PROJECT_CODE\暴哥代码\测试文件\DGM_0008971668_20231128\DICOM_4D_Qflow`；四方向为 Classic DICOM。不要选择其内部同名空目录。

生成的分割图像仍放在 `results_PCA`、`results_PCA2`、`results_R1`，Classic DICOM 文件名为 `DCM000_Sec_001.dcm` 等。最终 VTK 位于 `vtk`，时相文件名为 `NodeLiutexPressure_1.vtk` 等，索引名为 `timeseries.vtk.series`。这些名字与示例目录相同。输出目录直接回车即使用输入病例目录；也可以指定其他名为 `DICOM_4D_Qflow` 的目录。现有同名分割 DICOM、VTK、检查点和 `overall_flow_status.json` 会被覆盖；四方向原始 DICOM 与 `mask/root` 只读取，不由总入口写入。

## 步骤与检查点

| 编号 | 步骤 | 主要输出与检查点 |
| --- | --- | --- |
| 00 | 目录检查 | 四方向 DICOM 数量、mask/root 数量、外部程序路径 |
| 01 | 读取 DICOM | 形状、VENC、体素间距、时相数、时间间隔 |
| 02 | 相位边界归零 | 修正体素数、处理后数组形状 |
| 03 | 速度转换 | `velocity` 形状、分量顺序 RL/FH/AP |
| 04 | MSAC 背景校正 | 校正速度形状；用户选择后续使用原始或 MSAC 病例 |
| 05 | 分割辅助图像 | 三组 DICOM 的实际文件数和目录 |
| 06 | mask/root 导入 | 二值蒙版形状和非零体素数 |
| 07 | 自动解混叠与方向选择 | RL/FH/AP wrap 数、用户选择的反向分量 |
| 08 | Mask 裁剪及网格 | 裁剪范围、表面和四面体节点/单元数 |
| 09 | Gaussian 平滑与 DFW | 裁剪速度形状、DFW 输出形状 |
| 10 | 节点采样、压力、Liutex | 节点结果形状、内部子步骤耗时 |
| 11 | 最终导出 | `vtk` 文件数及索引路径 |

每步都会打印状态并更新输出根目录的 `overall_flow_status.json`。其中记录输入、选择、每步状态、耗时、数组形状、数据类型、输出路径和错误信息；失败步骤另保存完整 Python 调用栈。`--save-arrays` 会额外在 `checkpoints` 下保存关键 `.npy` 数组，便于之后按模块比对；真实病例数组很大，使用前请确认磁盘空间。状态文件不包含可用于恢复运行的完整数据，重跑需要重新计算。

MSAC 阶段在总入口中复用归一化速度和校正相位的原有数组，并按时相重新编码 AP/FH/RL，以降低同时保留的整例五维数组数量。选择 `raw` 时不生成后续不会使用的 MSAC 相位 DICOM 数组。该内存处理已用小型合成数据与原包装函数逐值比较；尚未以完整病例重新验证峰值内存或端到端结果。

## 运行方法

在 PowerShell 中进入 `D:\PROJECT_CODE\暴哥代码\python_4Dflow`，并把 `src` 加入 Python 模块路径：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -m flow4d.overall_flow --help
python -m flow4d.overall_flow --check-only
python -m flow4d.overall_flow --run
```

也可以直接运行入口文件；不带参数时会逐项提示选择，效果与 `--run` 相同：

```powershell
& 'D:/anaconda/python.exe' 'D:/PROJECT_CODE/暴哥代码/python_4Dflow/src/flow4d/overall_flow.py'
```

命令行会提示选择病例目录、Classic/Enhanced 格式、后续使用原始或 MSAC 数据、是否反转 RL/FH/AP，以及输出目录；反转分量直接回车或输入 `none` 均表示全部不反转；输出目录直接回车即写回输入病例目录。CGALMesh 和 TetGen 默认从相邻 MATLAB 工程的 `iso2mesh-master\bin` 自动查找，优先使用 64 位 Windows 可执行文件；只有找不到时才要求选择。DFW 使用项目默认 DLL 或指定路径。也可以用 `--case`、`--format classic`、`--source raw|msac`、`--flip RL,FH`、`--output`、`--cgalmesh`、`--tetgen`、`--dfw-library` 在命令行给出选择或覆盖自动找到的路径。

`--check-only` 只检查目录、文件数量和所提供的外部程序路径，不读取完整像素，也不生成输出。`--run` 会执行大量计算和写文件，允许写入非空目录并覆盖同名生成结果；目录中其他不同名文件不会被清理。完成每一步后可查看 `overall_flow_status.json`。如遇错误，先看最后一个 `failed` 步骤与对应信息。

## DICOM 读取耗时核查

`overall_flow` 与用户提供的 DICOM→STL 参考脚本都调用同一 `load_dicom_case(..., expected_classic_timeframes=25)` 读取四组原始四维 DICOM。总入口现在分别记录 M、v1、v2、v3 的读取耗时。本例一次独立的只读测量为 M 12.218 秒、v1 12.259 秒、v2 10.954 秒、v3 11.033 秒，病例读取总耗时 48.407 秒。先前同一入口的记录还出现约 23、36、112 秒，故尚无证据表明入口采用了不同的像素读取算法或固定慢于参考脚本；也未据此改动 DICOM 像素解码逻辑。
## 本例第 7 步的内存峰值

本例曾在四维 Laplacian 解混叠时分配 `(240,240,81,25)` 的 `complex128` 数组（约 1.74 GiB）失败。总入口已在分割辅助图像导出后解除对旧 Classic/Enhanced 四维体数据的引用，在 mask 导入后释放不再使用的 mask/root 源体数据。FFT 频域乘法、除法及四维正弦/余弦 Laplacian 组合改为复用已有数组，计算顺序和公式保持不变。

已在小型奇数、偶数四维数组上对照修改前代码：FFT 的正向、逆向输出逐元素完全一致；四维解混叠圈数也逐元素完全一致。缩小数据 `(96,96,48,8)` 的独立进程对照中，旧写法峰值工作集/页文件占用为 457.4/881.0 MiB，新写法为 430.8/854.0 MiB，非零解混叠圈数均为 177008。该测量只覆盖缩小数据。**后续状态更新（2026-09-28 核实）**：本例已在当前机器上完整跑通全部 25 时相两次
（2026-09-25、2026-09-27），第 7 步未再出现内存失败，故"可用内存能否完成 25 时相"已由实际运行确认可行。
峰值内存本身仍未独立测量。
## 本例第 10 步的边界节点检查

本例的 `mask/root` 单独重建出与整体运行相同的网格：表面 8504 个节点、17004 个三角面；四面体 100111 个节点、604901 个单元。裁剪速度场的网格上限为 `[204, 58, 58]`，其中 90 个四面体节点位于网格上限之外，最大越界为 0.393 个体素。MATLAB 原流程的 `griddedInterpolant` 设为 `spline` 后默认也使用样条外推；Python 节点采样已相应允许有限坐标的样条外推，并继续拒绝 NaN/Inf 坐标。

已用本例真实网格中的 90 个边界节点加 10 个内部节点，采样一个解析线性速度场；结果全部为有限值，最大绝对误差为 `5.7e-13 mm/s`。这只验证了网格到节点速度采样的边界行为。压力、Liutex 和完整 25 时相后处理仍需在下一次运行中逐步检查。没有 `--save-arrays` 的前次运行未保存第 9 步 DFW 速度场，因此无法从该次失败点直接恢复。
## 与 `final_test` 的流程区别

用户提供的 `final_test` 脚本已在本例生成 `vessel_mask_surface.stl`。该脚本读取原始四方向 DICOM，生成分割辅助图像，读取 mask/root，再通过 marching cubes 将二值 mask 导出为患者 LPS 坐标中的 STL；它没有执行 MSAC、四维解混叠、DFW、CGAL/TetGen 四面体网格、压力或 Liutex。因此该 STL 是可独立检查的表面结果，不能代替总流程第 7–10 步的数值验证。

参考脚本的交互输入错误后重选和失败时打印完整调用栈已用于总入口。mask/root 的层序也已按本例 DICOM 空间位置核对：81 层的文件名排序与空间位置排序一致，未因此修改读取算法。
## 当前限制

- 制作 `mask/root` 仍需在外部完成；入口不会自动分割。导入模块检查文件数和像素形状，目前没有完整核对每层的 Image Position、Orientation 和 Pixel Spacing。
- CGALMesh、TetGen 与 DFW 的真实病例结果和 MATLAB 数值一致性仍待外部验证。现有 Python 工程没有捆绑 CGALMesh/TetGen 可执行文件。
- TetGen 在 Windows 上可能把中文可执行文件路径以本地编码写进 `.node/.ele/.face` 注释；读取器会在字节层去掉注释，再严格解析 ASCII 数值记录。已用本机 TetGen 的小网格验证读回，尚未以本例完整四面体网格验证。
- 最终后处理包含第 19 时相 LSQ 几何系数，因此不足 19 个时相的病例会在前置检查被拒绝。

  `NodeLiutexPressure_*.vtk` 及 `timeseries.vtk.series`、25 组 UVW `.dat` 与 FEMbrick `.plt`、以及 `surface_mesh.stl`。
  逐步耗时见各病例目录的 `overall_flow_status.json`。
